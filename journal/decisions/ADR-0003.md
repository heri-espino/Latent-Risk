# ADR-0003 — Separate source downloads from time-vintage research panels

**Date:** 2026-10-16  
**Status:** Accepted

## Problem
The user has a Windows PowerShell Conda virtual machine to download historical market and monetary data. The project needs credible raw-source evidence before attempting a pseudo-real-time latent-risk factor model.

## Alternatives
1. One script directly assembles a common model-input factor panel and assumes each date's macro figure was known then.
2. Fetch sources individually with provenance, save each run immutably, and later construct historically available panels only after auditing releases and revisions.
3. Never automate collection and require ad-hoc spreadsheets.

## Decision
Choose (2). A source catalog lists known Yahoo market tickers, verified FRED codes and optional Banxico codes. Downloaded CSVs and per-source hashes stay under `data/raw/downloads/<timestamp>/`, ignored by Git; a manifest records source IDs, URLs, times, numerical coverage, statuses and failures. Exit nonzero if any requested series fails.

## Rationale
Backfilling monetary aggregates at reference-month dates would fabricate availability and contaminate forecasting evaluation. Revised graph downloads are valuable exploratory historical data but not historical vintages.

## Consequences
Historical release calendars, index transformations, comparable sovereign yields and missing current Mexican money-stock series must be resolved before any source snapshot can be used in a pseudo-real-time run. The downloader's correctness is only validated by offline tests until the user's VM executes it against actual providers.
