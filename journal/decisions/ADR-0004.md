# ADR-0004 — Official provider acquisition without equating monetary concepts

**Date:** 2026-10-17  
**Status:** Accepted

## Context
After the first Banxico collection attempt, the study still lacked current Mexico M1/M2 and official international monetary histories. Historical FRED macro retrieval failed on the user's Conda VM, and UK/Euro/Japan sources were absent.

## Decision
Add a separate source-specific API adapter for European Central Bank BSI euro M1/M2; Bank of England IADB sterling M4 and SONIA; Bank of Japan time-series M1/M2. Register Banxico current-definition M1 `SF311408` and M2 `SF311418`, corroborated in existing independent API clients and official Banco de México CF807 aggregate labels. Preserve source labels, units and per-source manifest records. Add an audit command reading all immutable prior manifests.

## Alternatives considered
1. Treat BoE M4 as a direct M2 substitute and stack country aggregates without distinction — rejected as conceptually unsound.
2. Add country-adjusted descriptive monetary indicators, keep source-specific model inputs, and assess empirical comparability before fitting — accepted.
3. Reuse failed FRED-only downloads until a network problem resolves — rejected as the only acquisition route.

## Scientific and operational consequences
Macro month reference labels are not dates when data were publicly known. Dynamic euro-area composition, different money-stock definitions, seasonal adjustments, differing units and publication lags remain major confounders. Successful API retrieval is not enough to start pseudo-real-time tests. No live download against the new provider APIs was run by the assistant. Any unknown network/format issue must appear in the per-series manifest, never be silently treated as good data.
